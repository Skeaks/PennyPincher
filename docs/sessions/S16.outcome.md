# S16 outcome, 2026-09-08

Shipped, as a DRAFT: the instrument for the pilot, not the pilot. `docs/pilot/plan.md` and
`pilot.json` (metro, retailer, recruiting source, how the SKU list is produced, the
preconditions that set the start date, the report procedure); `tools/pilot-report`, the
brief's script, with five commands: `query` prints the `wrangler d1 execute --remote --json`
commands for a week's rows and the abuse flags, `week N` writes `week-N.md` + `.json` (panel,
cells over the week with one vote per panelist and suspects excluded, the API's 72 h view of
the same cells, the lever-probe rate by retailer re-paired from the uploaded rows, adapter
health, top SKUs), `skus` writes the top-200 list, `reconcile` replays every resolved cell's
votes under a sweep of `RESOLVE_SAFETY_FACTOR` and `MIN_TIER_SIGHTINGS` and prints the
premature-tier and premature-floor rates against the final resolution, `decide` applies the
brief's three rules and writes `decision.md`. 74 tests, no network; one drives the real Hono
app on the memory repos and checks the tool agrees with `GET /v1/cells` cell for cell.
`decision.md` is committed in its PENDING form with the rule written down. Gate green.

Why a draft. Three of the five acceptance items need two weeks of real data that does not
exist: the weekly reports, the recalibration, and the decision. `packages/stats` is untouched
because there is no evidence to change a constant on; `reconcile` produces that evidence when
there is data, and on synthetic uniform ladders it confirms 1.5 sits inside the 15% budget. The
counsel review is Jamie's. Metro and retailer arrived as "X" and "Y"; they are committed as
given, flagged as placeholders in both files, the tool refuses to run until `retailer` is a
real one, and the plan recommends Target and the 085 / 086 area with the reasons.

What the brief got wrong. (1) "A script that reads the API": the API has no listing endpoint
and should not get one, so the enumeration comes from a D1 export and only the per-cell
resolution and adapter health come from the API. Adding a summary route would have reached
into `apps/api` (outside `owns:`); the export is the honest path and it is reproducible from
the printed command. (2) The weekly numbers and the API's numbers cannot be the same numbers:
the endpoint's window is 72 h and a pilot cell rarely reaches the threshold inside it. The
report resolves over the week with the endpoint's own dedupe and prints the API's view next to
it; the decision is computed over the whole pilot window. Jamie should confirm that reading
of "cells RESOLVED". (3) "Lever-probe difference rate by retailer": the extension's verdicts
are never uploaded (S06, by design), only the pair of observations is. The tool re-pairs them
(same panelist, retailer, SKU, within the hour) and re-applies `compare.ts`'s store rule,
including the Instacart location-only rule. (4) The decision rule has no minimum sample; 20%
of three cells is a coin flip. Two minimums (20 resolved cells, 50 comparable checks) are in
`pilot.json` with an INCONCLUSIVE verdict below them: this session's proposal, Jamie's call.
(5) `tools/pilot-report` is not in `owns:`, but the brief names it; written, like
`docs/webstore.md` in S15. `pnpm-lock.yaml` changes because it is a new workspace package.

What was harder than expected. Deciding what a premature resolution is: the replay judges the
first RESOLVED prefix against the final resolution on both tier count and floor, and it is the
floor rate that governs the recommendation because that is the number the engine must not get
wrong. A sticky panel with an 8% floor over 40 observers fails every factor up to 3, which is
correct: no safety factor waits for a tier the panel has not yet drawn, and the recommendation
text says so instead of proposing a number. Biome's import sorting moved a module comment below
the first import in one file; fixed by hand.
