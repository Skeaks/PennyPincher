The blocker, resolved. `test/probe/probe.test.ts` ("for garbage or a retailer with no
adapter") used a Target observation as its example of a retailer with no adapter. With the
Target adapter registered it reported `no_price` instead of `no_adapter`. Left untouched in the
first push (rule 1, outside `owns:`), fixed on Jamie's instruction the same afternoon with the
one-liner proposed in the PR: `probeDeps({ fetchPage, adapters: [] })`, which keeps the
"no adapter" path exercised now that every retailer in the schema enum has one.

Second half, same day: listing tiles for both retailers. Jamie asked for search-page prices
after loading the build. No fixture existed, so with Jamie's permission the session recorded
the two search pages from Jamie's own Chrome tabs (`/s?searchTerm=banana` at Durham,
`/search?q=banana` at East Windsor), stripping them in-page with the scrubber's own tag and
attribute rules (a public page cannot POST to localhost, and the clipboard was the only
transfer that kept 400 KB out of the transcript), then `pnpm scrub --name` and `--check`, both
clean. This deviates from docs/fixtures.md's "a human records"; the sidecar notes say so and
`fixtures-reviewed` is Jamie's. Target tiles: the grid's `ListingPageProductListing` (title from
the content link's `aria-label`, in product-page form; price the first rich-text dollar amount;
unit price, Pickup / Delivery lines) and the carousel `productCardVariantMini` (price block,
strikethrough reg price, "Sale", `PromoDetails`); grid tiles are read first so a product shown
in both keeps its results rendering. Walmart tiles: `[data-item-id]` inside `item-stack`, priced
from the price block's `aria-label` ("Price $ 0.06 each (est.) 16.0 ¢/lb …", because the visible
digits are split across spans), was-price and unit price from the same label, fulfilment from
the first badge line, store from the header banner (which also becomes the product page's
fallback). Neither retailer selects a fulfilment on a listing, so every tile is
`fulfillmentInferred`. Listing URLs: Target `/s`, `/c/`, `/b/`; Walmart `/search`, `/browse`,
`/shop`. 805 tests in the gate after this.

What the brief got wrong. (1) "No new fetch call site" and "add a postAdapterHealth function"
conflict with the posture pin's `toHaveLength(2)` on `fetch(\`${config.apiBaseUrl}`; resolved by
factoring the upload's fetch into one `postJson` helper that both POSTs share, so the file still
has exactly two call sites and the pin is untouched. (2) The Target trap is not quite as the
brief says: on all four fixtures `[data-test="product-price"]` is the sticky bar's copy and the
hero box renders its price as `text-quill-insert-0`; the adapter reads whichever holds a number
and the skeleton case (both empty) is a counted `no_price` with detail "price box empty",
tested by emptying the copies. (3) `capture/tally.ts` does not cover the counting: it is a
per-listing-URL count for the popup; health is per adapter by reason, so `health.ts` keeps its
own. (4) No fixture showed a Target or Walmart search page when the brief was written; the first
push shipped without tiles and asked for captures, the second half recorded them (above).
Quick-view modals are still unrecorded and unhandled. (5) The API `owns:` (three
files) cannot mount a route: `app.ts` (register + optional `adapterHealth` dep) and `index.ts`
(D1 binding) each got two lines. Both S11 precedents.

What was harder than expected. Walmart's `textContent` joins adjacent leaves with no
separator ("Pickup fromEast Windsor SupercenterPickup as soon as 3pm"), so the zone-2 fallback
reads leaf texts joined with spaces, the same trick the Instacart adapter uses. Target's cell
label "pickup - selected - 1 of 3" defeated a `\b-` word boundary (space and dash are both
non-word), fixed with a negative lookbehind on "unselected". Fulfilment defaults with no
control on the page are a guess in both adapters (`ship`, inferred, flagged); no fixture shows
that state.
