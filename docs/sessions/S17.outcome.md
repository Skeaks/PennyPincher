uses `aria-modal` + `aria-label`, and five other dialogs (welcome, cart, profiles) sit on the

tile's store and fulfilment come from its row and the tile collector dedupes by product URL

that carries a Product block. (2) The probe did not fail on "no price": the anonymous HTML has the price label; it
failed on `no_fulfillment` (no service-type control). (3) `tools/scrub` strips every
`<script>`, so no committed fixture can carry JSON-LD; the JSON-LD path is tested on a copy of
the scrubbed page with the raw block put back (verbatim in the test). A scrub rule that keeps

suffix for a `logged_out` sidecar, so the fixture is
`walmart-whole-milk-1gal-anonymous-fetch-logged-out.html`, not the brief's name. (5) The
sidecar requires a store id; on the anonymous page 151190 (`retailerLocationId`) exists only

What was harder than expected. The anonymous page was served for ZIP 191xx (Philadelphia),
not the recorder's 085: an anonymous fetch resolves to a different Walmart location, and
because the DOM shows no location id, `compare` falls back to the label ("Walmart") and calls
the stores the same. For Instacart storefronts the label is the banner, not the location, so
the verdict can compare two locations. Decided (Jamie, 2026-09-07): Instacart never matches
on the label; a pair without a location id on both sides is `store_unknown`. So the probe on
the milk page parses and stores the anonymous row but says "Could not check" until the
anonymous HTML exposes a location id (`compare.ts`, `labelNamesLocation`). JSON-LD price wins over
the DOM price by the brief's rule; on a logged-in page they could differ if Instacart server-renders
a base price, and the test pins the rule so a reviewer sees it.
