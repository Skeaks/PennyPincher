# S13 outcome, 2026-09-07

Shipped. `packages/normalize`: `normalizeUpc` (8/12/13/14 digits, UPC-E expansion, GS1
check digit, GTIN-14; a failing code is treated as absent, never merged), `parseSize` (fl oz /
gal / qt / pt / l to ml, oz / lb / kg to g, ct / pack of N / N pack / each to a count, a
missing count is 1), `signature` (brand + title tokens: marks and punctuation out, stopwords
out, plural fold, `2%` as `2pct`, size expressions removed), `matchProducts` (Dice similarity
over the token sets, gated by size conflict, explicit-brand conflict and a one-sided variant
attribute such as organic / frozen / 2% / strawberry; `FUZZY_THRESHOLD` 0.8) and
`canonicalize(product, { candidates })` (`gtin:<14>` at confidence 1; the best candidate above
threshold at the match score; else a deterministic `fuzzy:<sorted tokens>@<size>` key at a
0.5 to 0.9 heuristic; `none` for an empty title). 60 tests. `__golden__/pairs.json`: 100
pairs, 46 same / 54 different, every fixture-sourced side drawn from the real product pages
and the three search fixtures' tiles (131 tile titles extracted with happy-dom), composed
variants (unit conversions, reorderings, tile-vs-page forms, five UPC cases) marked
`source: "composed"`. `test/golden.test.ts` gates precision on "same" at 0.97 and prints
recall. On the proposed labels: precision 1.000, recall 0.913 (42 tp, 0 fp, 4 fn). The four
misses are all generic produce across retailers ("Fresh Banana, Each" vs "Bananas, Sold by
the Each" vs "Fresh Banana - each - Good & Gather™", and a 2 lb organic banana bag), where
the titles simply share too few tokens; deliberately not chased, because loosening the
threshold or discounting a one-sided brand would start merging store-brand milks.
`apps/api`: migration 0003 (`products`, `product_skus`, `product_tokens`, two nullable columns
on `observations` and an index on `(canonical_cell_key, observed_at)`); `repo/products.ts`
(interface, per-batch `resolveIdentities`, memory repo, SQL) and `repo/products-d1.ts`
(the D1 half, split like adapter-health because the extension typechecks `app.ts`); ingest
resolves one identity per distinct (retailer, SKU) before building rows, so every row stores
`canonical_id` and `canonical_cell_key` = `canonicalId|fulfillment|zip3`; a SKU once linked
keeps its id; `listByCanonicalCell` on both repos. 17 API tests. 925 in the gate.

What the brief got wrong. (1) `owns:` names one API file, but "ingest stores canonical_id on
each observation" and "cell_key gains an alternative" cannot be done without `observations.ts`,
`d1.ts`, `memory.ts`, `app.ts`, `index.ts`, a migration and the D1 column test (which now also
reads the ALTER TABLE lines of 0003); all called out in the PR, S12 and S14 precedents.
(2) "`canonicalize(product)` ... fuzzy uses token-set similarity" needs something to be similar
to; the function takes optional candidates, and the API supplies products sharing a title
token. Without candidates the fuzzy id is exact-after-normalisation. (3) The golden file is
human-owned by rule 3 yet did not exist; the session created it with `status: "proposed"` and
notes on the pairs it was least sure of (identical marketplace titles under two ids, an
en-dash-only difference on a variant parent listing, and the generic-produce "same"s).
Relabelling is Jamie's; if the harness then fails, the matcher is wrong.

What was harder than expected. NFKD spells "™" as "TM", which became a token until the marks
were stripped first. "128 oz" on a milk tile is a weight in the parser's eyes (3629 g) while
"1 gal" is a volume, so those two never share a dimension and compare as unknown, not agree;
the tile pairs that matter carry "fl oz" or "gal", so it did not bite the golden set, but a
retailer that writes milk in plain ounces will read as a different key. Bash heredocs broke
on apostrophes again (S07, S14); source went through the editor tool.

Not done, deliberately: no backfill of `canonical_id` for rows ingested before 0003 (raw_json
has what a script needs); `GET /v1/cells` does not accept a canonical cell key (the repo
method exists; the route is cross-retailer UI territory, out of scope); no admin view of the
products table. Follow-ups for Jamie: label `__golden__/pairs.json` and set `status:
"reviewed"`; mark S13 done in `docs/sessions/README.md`; `apps/api/README.md` does not
mention the products tables.
