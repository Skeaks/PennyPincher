# S03 outcome, 2026-09-04

Shipped: schema `1.0.0`, every field commented with the fixture(s) that show it or "context";
`docs/migrations/1.0.0.md`. Added `facts.priceText` (required; every sidecar already had it)
and `facts.isEstimate` (Instacart and Walmart by-weight produce). Made `store.retailerStoreId`
optional with an at-least-one-of rule, because Walmart never renders its store number. Dropped
`in_store`, `app`, and the three retailers without fixtures. `packages/synth`: `generateLadder`
with `probabilities`, `floorRarity`, `plantFloor`, `stickiness`, `observers`, `shell`; a
seeded PRNG so `sample(n)` is a prefix of `sample(n + m)`; coupon-collector helpers
(`k·H_k`, exact inclusion-exclusion, `3/p`) and a README table the tests assert. 25 tests.

What the brief got wrong: the fixture audit needed the scrubber's parser (parse5 in
`tools/scrub`) to read attributes, not just text, because the store ids and SKUs live in
`id` attributes. `floorRarity` and `plantFloor` overlap; both exist, documented as "pin the
existing floor" vs "add a new one". Two files outside `owns:` had to change or the gate
would go red: `apps/extension/test/fixtures.ts` and `apps/extension/test/store.test.ts` pinned
`"0.1.0"` as a literal. Both now import `SCHEMA_VERSION`; the fixture also gained `priceText`.
Called out in the PR body. The "pins the schema version" test in `packages/schema` changed its
expected literal from 0.1.0 to 1.0.0 because the brief's acceptance says so, not to pass.

What was harder than expected: deciding which field owns the "(est.)" qualifier. The integer
loses it, `priceText` carries it verbatim, and a boolean the stats engine can filter on was
still needed, hence both. Otherwise nothing structural.

Not done, deliberately: `tools/scrub/src/meta.ts` still lists `in_store` in its own
`FixtureFulfillment` enum. It does not import the schema, no fixture uses the value, and the
file is outside `owns:`. Follow-up: point it at `Fulfillment` from `@pennypincher/schema`.
