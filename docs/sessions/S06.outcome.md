# S06 outcome, 2026-09-04

Shipped: `apps/extension/src/probe/`: the probe flow (`probe.ts`, every collaborator
injected), the same-store comparison (`compare.ts`: store id first, label as the fallback for
Walmart which never renders its store number, `store_unknown` when neither matches), the rate
table + result cache + per-retailer counters on `chrome.storage.local` (`state.ts`), the one
network call in the extension (`fetch.ts`: `credentials: "omit"`, `cache: "no-store"`,
`redirect: "manual"`, so a redirect to anything is `redirected` and the target is never seen),
the content-script side (`content.ts`: report stored observations; parse fetched HTML with
`DOMParser` and the same adapter), the background wiring (`background.ts`: `onMessage`, an
hourly `pp:probe-prune` alarm), and the options-page summary (`summary.ts`). `src/popup/`: a
pure view model (`model.ts`) and the minimal popup ("Your price", "Anonymous price", one of
the five verdict lines). 90 new tests in `test/probe/`, all on fixtures or synthetic pages.
Manifest unchanged. `check-forbidden-api.sh` clean.

Draft, for one reason: `test/posture.test.ts` ("no network", S04) fails on `probe/fetch.ts`.
That block pinned a world where nothing fetched; ADR 0003 line 2 and this brief say one file
now does. Editing that test is outside `owns:` and it is the extension's legal posture, so it
is Jamie's call. `test/probe/posture.test.ts` is the proposed successor: exactly one source
file calls `fetch`, it is `probe/fetch.ts`, it omits credentials and never follows redirects,
and every other network or session API stays banned. Dodging the old regex (calling through a
`typeof fetch` parameter) would have passed the gate and made the test meaningless, so no.

What the brief got wrong: a MV3 service worker has no `DOMParser`, so "parse with the same
adapter (DOMParser)" cannot happen in the background without the `offscreen` permission (a
manifest change the brief forbids). The background fetches and hands the HTML back to the
content script that reported the observation, which parses it detached and returns the
`ExtractResult`. If that tab is gone the result is `extract_unavailable`. Second: there is no
login-wall fixture. The "Could not check" test uses a synthetic auth-modal page with no price;
a real recording (fixtures/, Jamie) would be better. Third: no Target adapter exists until
S12, so the Target `STORE_DIFFERS` pipeline test runs through a sidecar-backed stand-in adapter
that only checks the sidecar's price text is in the HTML it was handed; the pure comparison
test on the Target pair needs no adapter. Fourth: the brief says `retailerStoreId` must match;
Walmart never renders one, so labels are the fallback there. Judgment call, easy to reverse.

Outside `owns:`, unavoidable, each a few lines: `entrypoints/background.ts` (register the
probe), `entrypoints/instacart.content.ts` (report outcomes, answer extract requests),
`entrypoints/popup/main.ts` (now a shim over `src/popup`), `entrypoints/options/main.ts`
(probes table; "Delete my data" also clears probe state; the "Sent anywhere" line no longer
says "no network requests"), `styles.css` (two rules).

user "This version of the extension makes no network requests of any kind". That is false

`apps/extension/README.md` still says "no network at all". `docs/sessions/README.md`: mark S06
done. Fulfilment is not part of the verdict (the anonymous page shows its own default); both

Decision data: every probe stores the pair in the observation store, so "Export my data" is

checks, differences and failures per retailer, with failures by reason.
