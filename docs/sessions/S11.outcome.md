# S11 outcome, PR 1 of 2 (API half), 2026-09-07

Shipped: `GET /v1/cells/:cellKey` in `apps/api`. Reads the cell's last 72 h through a new
`ObservationRepo.listByCell` (D1 on the `(cell_key, observed_at)` index, Map in tests),
collapses the rows to one vote per panelist (latest `observedAt`; ties on `receivedAt`, then
`observationId`), runs `resolve()` over the votes and returns `{ cellKey, resolution, n,
panelists, observations, latestObservedAt, updatedAt, summary, windowHours }`. Same bearer
check as ingest, factored into one `denied()` helper. Cached at the edge via `caches.default`
with `Cache-Control: public, max-age=60`, keyed on the URL after the bearer check. 19 tests,
no network; the brief's synth case (stickiness 1, 10 observers, 200 draws) reports `n: 10`,
`observations: 200`, `UNRESOLVED / insufficient_n`.

What the brief got wrong: `owns:` lists only `routes/cells.ts` and `cells.test.ts`, but the
route cannot exist without touching `app.ts` (mount, shared bearer check), the repo interface
and both implementations (`listByCell`), `index.ts` (the cache binding) and `package.json`
(stats as a dependency, synth for the test). All inside `apps/api`; the extension half is
untouched. Also, `n` and `panelists` are the same number by construction once the dedupe
runs, so the response carries `observations` (rows before the collapse) as the count that
actually differs; without it a client cannot tell that dedupe happened. The brief's ten-observer
case needs a five-tier ladder: with three tiers, ten independent votes can clear the coupon
threshold (9) and resolve, which is correct behaviour but not the `insufficient_n` the brief
asks for.

What was harder than expected: nothing in the endpoint itself. Two small traps. `ObservationRow`
is flat (`priceMinor`, `currency`) while the resolver wants `facts.price`, so the route maps
rows to `ObservationLike` explicitly. And ISO timestamps are only lexicographically
chronological within one precision ("...:18Z" sorts after "...:18.000Z"), so the D1 range
query widens its bounds by a second and the route re-filters exactly.

Not done, deliberately: the extension half (sync alarm, ladder popup) waits for S17 (#26) to
merge, per the brief; it is PR 2 and branches from `main` after that. `facts.isEstimate`
observations are still not filtered (S09 flag stands). No row limit on the cell query; a pilot
cell will not exceed a few hundred rows in 72 h, and S14 owns ingest limits.

Outside `owns:`: the `apps/api` files listed above, `apps/api/README.md`, and `pnpm-lock.yaml`
(two workspace links). Follow-up for Jamie: mark the API half done in `docs/sessions/README.md`.

# S11 outcome, PR 2 of 2 (extension half), 2026-09-07

Shipped as a DRAFT: `apps/extension/src/sync/` (config from `WXT_API_BASE_URL` /
`WXT_PILOT_TOKEN`, staging URL by default and no token by default; `pp:sync` state with the
sent-id map and the backoff; the transport for `POST /v1/observations` and
`GET /v1/cells/:cellKey` with `credentials: "omit"`, `redirect: "error"`; `runSync` in batches
of 200, one alarm every 15 minutes, off until consent, exponential backoff 15 min to a day,
rows never marked sent on failure) and the ladder in the popup (`popup/ladder.ts`: bars by
share, the user's tier and the floor labelled, the API's explain line, RESOLVED / UNRESOLVED
with "Needs N more observations" / NO DATA, plus "You contributed N observations this week"
from the sent map). Built on S17's popup model unchanged; the ladder is appended whenever
the popup has the user's own price for the page. 41 new tests; `wxt build` passes with the
staging URL and no token in the bundle.

Why it went up as a draft, and how it left draft: `test/probe/posture.test.ts` pinned that
exactly one source file calls `fetch`, and it is the probe's. The upload needs a second call
site. That test is the S06 legal pin and Jamie's to change (the S06 precedent: draft PR #16,
decided by Jamie), so the PR opened with it failing and the proposed replacement in the body.
Jamie decided the same day (2026-09-07): the first-party upload is in posture. The pin is now
two files, the probe's with its existing assertions and `sync/transport.ts` pinned to
`credentials: "omit"`, `redirect: "error"`, `cache: "no-store"`, every URL built from the
configured API origin and no literal host in the file. No agent edited that test on its own
initiative; the change was made on Jamie's instruction in this session.

What the brief got wrong: "token from build-time env, committed as staging by default"
cannot be done for the token: the pilot bearer is a `wrangler secret` and gitleaks runs on
the gate, so only the URL defaults to staging and the token comes from `.env` (gitignored;
`.env.example` committed). Without a token the extension sends nothing and the popup says
"no panel access configured". The brief's `owns:` again undercounts: consent copy and
`CONSENT_VERSION` (now 4) had to change because the v3 copy said the probe's page request
was the only network request; `entrypoints/background.ts` registers the alarm; `styles.css`
got the bar styles; `.env.example` is new. Each is called out in the PR.

What was harder than expected: nothing technical. The consent copy for "Delete my data" now
says records already sent to the server are not removed by it (S14 owns the endpoint); that
sentence is claims copy and Jamie's to word. `stats` is not a dependency of the extension:
`formatMinor` and `cellKey` are mirrored in `popup/ladder.ts` with a comment saying so.

Not done, deliberately: the options page does not clear `pp:sync` on "Delete my data"
(outside `owns:`; harmless, the map prunes itself). `detectShift` is not shown; the S10
README says not to for inconclusive cells and the API does not expose it yet. Follow-ups for
Jamie: the posture test decision; mark S11 done in `docs/sessions/README.md`.
