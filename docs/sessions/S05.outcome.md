# S05 outcome, 2026-09-04

Shipped: `apps/extension/src/capture/`: the `Adapter` contract (`adapter.ts`: `matches(url)`,
`extract(doc, ctx)` returning `{ ok, observation | reason }`, never throws), `PageContext`
with optional `fulfillment` / `sessionState` / `cleanSession` overrides for the S06 probe, the
Instacart adapter (`adapters/instacart.ts`, selectors documented at the top of the file), a
DOM-side scrub + SHA-256 evidence hash (`evidence.ts`, `sha256.ts`), money parsing, a page
context builder (device class from viewport width and pointer type, never the UA), the
panelist id (`panelist.ts`, 7-day rotation), and the capture runner (`run.ts`: consent check
before the adapter runs, dedupe per rendering, MutationObserver with a 500 ms debounce). One
content-script entrypoint, `src/entrypoints/instacart.content.ts`. 94 new tests; all four
Instacart fixtures extract to their sidecars and complete to schema-valid observations.

What the brief got wrong: two files outside `owns:` were unavoidable and are called out in the
PR: `src/entrypoints/instacart.content.ts` (WXT registers content scripts from that
directory; it is a 14-line shim over `capture/run.ts`) and `apps/extension/package.json` +
lockfile (happy-dom as a dev dependency, because tests need a `Document` from fixture HTML).
"Fulfilment and session state from the page" cannot be the content script's job: it is
retailer-specific, so the adapter reads them and `PageContext` carries them only as overrides.
`ExtractResult.observation` is the page-derived part (`AdapterObservation`); ids, clock and
client version are minted by the runner. The sidecars' `expected.priceText` is "$0.22", not
"$0.22 each (est.)" as `packages/schema` comments suggest; the adapter follows the sidecars
(acceptance criterion) and puts the qualifier into `isEstimate`. "store (retailer slug)":
the schema's `StoreRef` has no slug field, so `retailerStoreId` is the numeric id from
`#item_details-items_10769-<sku>` (matches the sidecars) and `label` is "Wegmans".

What was harder than expected: mixing vitest fake timers with happy-dom's own real-time
mutation queue was flaky, so `watchPage` takes an injectable timer and the tests crank it by
hand. Adjacent text nodes concatenate with no separator in `textContent`, which turned
"$0.59 / lb" + "Final cost by weight" into "lbFinal"; unit price is now matched per element.
Instacart has no positive logged-in indicator: the logged-in pages simply lack the "Log in"
button and the auth modal, so `logged_in` is "header rendered and no logout indicator", and
`unknown` only when there is no header at all. The fixtures scrub the ZIP, so `zip3` is
exercised by un-scrubbing a copy of the bananas page in the test, not by a fixture.

Not done, deliberately: `wasPrice`, `promoTags` and `memberPrice` have no Instacart fixture
showing them; the shapes ("Original price:" screen-reader span, `<s>`/`<del>`, badge text,
"Instacart+") are best guesses and the tests only pin that the fixtures yield none. A capture
with a struck price would let S12 confirm them. `docs/fixtures.md`'s `expected` block does
not cover `unitPriceText`, `sizeText` or `brand`, so those are asserted per fixture by hand.
