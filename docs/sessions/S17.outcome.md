`0.2.0`: JSON-LD first (`capture/jsonld.ts`, retailer-agnostic; a block is trusted only when it
names the page's SKU, because an SPA keeps the `<head>` of the page it first loaded), the hero

`Adapter.extractTiles` on the generic collector in `capture/tiles.ts` (one row per SKU, skips
counted by reason), `captureOnce` stores every priced tile on a search / aisle / storefront URL,
`startCapture` keeps a per-page count in `capture/tally.ts` and the popup shows "N prices on
this page recorded." `canonicalUrl` now keeps `retailerSlug`, because the modal's URL names the

What the brief got wrong. (1) The two logged-in fixtures (modal, search) were not in
`fixtures/raw/`; only the anonymous fetch was. The modal is handled by shape and tested on a
dialog built from a rendered page; tiles are tested on the recommendation carousels of the
recorded product pages (the same tile markup) and on synthetic Rollback tiles. Both need the
real recordings to confirm the selectors: scrub them, and the per-fixture tests in
`test/capture/instacart.test.ts` and `tiles.test.ts` want a `-modal` and a `-search-` case
added. (2) The probe did not fail on "no price": the anonymous HTML has the price label; it
failed on `no_fulfillment` (no service-type control). (3) `tools/scrub` strips every
`<script>`, so no committed fixture can carry JSON-LD; the JSON-LD path is tested on a copy of
the scrubbed page with the raw block put back (verbatim in the test). A scrub rule that keeps
`application/ld+json` is a follow-up for Jamie. (4) The scrub gate requires a `-logged-out`
suffix for a `logged_out` sidecar, so the fixture is
`walmart-whole-milk-1gal-anonymous-fetch-logged-out.html`, not the brief's name. (5) The
sidecar requires a store id; 151190 (`retailerLocationId`) exists only in the hydration
scripts, so the sidecar records it and the test asserts the DOM yields the label alone.

What was harder than expected. The anonymous page was served for ZIP 191xx (Philadelphia),
not the recorder's 085: an anonymous fetch resolves to a different Walmart location, and
because the DOM shows no location id, `compare` falls back to the label ("Walmart") and calls
the stores the same. For Instacart storefronts the label is the banner, not the location, so
the verdict can compare two locations. Decided (Jamie, 2026-09-07): Instacart never matches
on the label; a pair without a location id on both sides is `store_unknown`. So the probe on
the milk page parses and stores the anonymous row but says "Could not check" until the
anonymous HTML exposes a location id (`compare.ts`, `labelNamesLocation`). JSON-LD price wins over
the DOM price by the brief's rule; on a logged-in page they could differ if Instacart server-renders
a base price, and the test pins the rule so a reviewer sees it.
