The blocker. `test/probe/probe.test.ts` ("for garbage or a retailer with no adapter") uses a
Target observation as its example of a retailer with no adapter, with a comment two tests
later saying "No Target adapter until S12". With the Target adapter registered the probe now
runs it and reports `no_price` on the stub HTML instead of `no_adapter`. Rule 1 says never
edit a test to make it pass, and `test/probe/**` is outside `owns:`, so it is untouched and
red. Proposed one-line fix for Jamie: pass an empty registry in that test,
`probeDeps({ fetchPage: fetch.fetchPage, adapters: [] })`, which keeps the "no adapter" path
exercised now that every retailer in the schema enum has one. Everything else in the gate is
green (lint, typecheck, 783 tests, guards).

conflict with the posture pin's `toHaveLength(2)` on `fetch(\`${config.apiBaseUrl}`; resolved by

has exactly two call sites and the pin is untouched. (2) The Target trap is not quite as the
brief says: on all four fixtures `[data-test="product-price"]` is the sticky bar's copy and the
hero box renders its price as `text-quill-insert-0`; the adapter reads whichever holds a number

files) cannot mount a route: `app.ts` (register + optional `adapterHealth` dep) and `index.ts`

non-word), fixed with a negative lookbehind on "unselected". Fulfilment defaults with no
control on the page are a guess in both adapters (`ship`, inferred, flagged); no fixture shows
